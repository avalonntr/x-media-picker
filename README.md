# X Media Picker

Hold **Alt** and click any image or video on X — it is added to a download list. Alt+click the same media again to remove it. Without Alt, the page behaves exactly as before.

Videos are saved as the **highest-resolution MP4** X actually serves, never the poster frame and never a "post link". Photos are saved at **original resolution with their real format** (`?name=orig`, correct `.jpg` / `.png` / `.webp`).

## Why a video click needs more than reading `src`

X plays video through Media Source Extensions, so `<video>.src` is `blob:https://x.com/…` — even the browser's own *Copy video address* has nothing usable. This extension reads the post the video belongs to, asks the post payload for its media (`cdn.syndication.twimg.com`, falling back to `api.fxtwitter.com`), and stores the real MP4 URL:

```
Alt+click on a video  ->  https://video.twimg.com/…/1920x1080/xxxx.mp4?tag=14
```

## What it saves

| Clicked | Saved |
|---|---|
| Photo | original resolution, real container (`name=orig`) |
| Video | highest-resolution progressive MP4 |
| GIF post | the MP4 X stores it as (X has no `.gif` source since 2014) |
| Poster frame | **not** the poster — the post's real MP4 |
| Avatar | `_400x400` (largest X keeps) |
| Profile | avatar + banner |

## Install (unpacked)

1. Download the zip from [Releases](../../releases), **unzip** it (the folder must survive).
2. Open `edge://extensions` (or `chrome://extensions`) and enable **Developer mode**.
3. **Load unpacked** → pick the unzipped folder.
4. Reload any X tab that was already open.

Chinese step-by-step: [`INSTALL.md`](INSTALL.md).

## Two builds

| Build | Injection | Capability |
|---|---|---|
| `-x-only` | x.com / twitter.com | full: video resolution, original photos, GIF, profile art |
| generic | all sites | images (incl. lazy-loaded and CSS `background-image`), direct `<video src>` links, `og:video` when the page publishes it |

The generic build **cannot** do X-style resolution: that needs per-site logic, and guessing it would be lying to you. Build both with `node tools/package.mjs`.

## How it works

```
click -> resolveElement()  find the media under the cursor (the clickable layer of a
                           video is a *sibling* of <video>, so the search climbs the
                           tree up to the post boundary)
      -> describeNode()    media -> {kind, url};  blob/poster -> post link
      -> background.js     post link -> real MP4 via syndication, then list
```

The list lives in `chrome.storage.local`; popup offers delete / download all / copy / export.

## Permissions

- read media URLs on the pages you point at (for the x-only build: x.com, twitter.com, and `*.twimg.com` / `api.fxtwitter.com` for the resolution request);
- store one list and trigger browser downloads.

No account, no cookies, no telemetry, nothing leaves the machine except the post-id lookup above.

## Development

```powershell
node test/pick.mjs        # pure logic: URL classification, upgrade rules, toggles
node test/content.mjs     # event wiring against a fake DOM + fake chrome
node test/resolve.mjs     # post payload -> MP4, with stubbed network
node test/background.mjs  # real background.js against fake chrome (list state)
node test/core-sync.mjs   # generated pick.core.js is in sync with pick.js
node test/e2e-edge.mjs    # real Edge + CDP: dispatches an actual Alt+click
```

`test/e2e-edge.mjs` launches a throwaway Edge profile (headless, own `--user-data-dir`), loads the extension, and drives it with real key/mouse events through the DevTools Protocol — no screenshots, assertions are read back from `chrome.storage.local`.

```
ok  Alt keydown puts the page in pick mode
ok  hovering marks the media element            — IMG|crosshair
ok  Alt+click added exactly one entry           — …?format=jpg&name=orig
ok  plain click changes nothing
ok  poster click resolved to the real MP4       — video.twimg.com/…/1920x1080/….mp4
ok  clicking the video body targets the same MP4
```

`pick.core.js` is generated from `pick.js` by `tools/build-core.mjs` (content scripts are classic scripts and cannot use `import`). Icons are generated by `tools/make-icons.mjs`; zips by `tools/package.mjs` (hand-written ZIP, zero dependencies).

## Limitations

- fullscreen player outside the post is handled through the URL's post id; protected/deleted posts fall back to the post link with a visible message;
- no `<canvas>`-drawn media;
- iframes are not scanned (`all_frames: false`);
- the list lives and dies with the extension.
